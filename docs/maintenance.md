# 维护约定

## 文件职责

- `stash/` 维护 Stash 主配置、规则集和覆写。
- 主配置负责策略组与规则顺序；独立规则集仅保存匹配条件。
- 初始化模板内置示例规则。启用独立规则集后，移除对应内置规则，在规则集内维护，避免重复。
- Stash 覆写按需启用，不默认安装第三方脚本或规则。

## 第三方模块

优先引用作者的原生 Stash 覆写；没有原生版本时，使用 [Script Hub](script-hub.md) 转换并维护来源链接。只有需要额外接口修正、二进制兼容或 Stash 参数表单时，才在本仓库维护适配文件。保留作者署名和来源；更新转换器及上游后仍需检查下载与实际命中。

## 添加规则

1. 在客户端请求记录中确认需要处理的域名和流量。
2. 优先使用精确 `DOMAIN`；需要同时匹配根域和子域时使用 `DOMAIN-SUFFIX`。
3. 放行规则放在广告拦截之前；兜底规则始终位于最后。
4. 根据当前加载方式修改主配置或独立规则集，并在变更说明中记录原因、来源与验证结果。
5. 在 Stash 中重新加载配置或更新规则集，确认命中策略并检查常用服务；如有误拦截，添加更精确的放行规则。

## 提交前检查

- 确认 YAML 缩进、策略名称和规则顺序正确。
- 检查远程资源 URL 可访问，且返回的是原始配置文本。
- 用 `git diff --check` 检查空白问题，用 `git diff --cached` 查看即将提交的内容。
- 确认没有订阅地址、节点密码、令牌、私钥或个人证书。`.gitignore` 不能保护已经被跟踪的文件。
- 需要真实客户端加载与请求验证才能确认运行效果；文本语法检查不能替代客户端验证。
